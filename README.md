# Ollama Chat — чат с локальной ИИ в Godot

Маленькое приложение на Godot 4, которое общается с локальной моделью через
[Ollama](https://ollama.com). Никаких облаков и API-ключей: всё работает на вашей
машине, ответ печатается потоком, поддерживаются Markdown, отмена генерации,
собственные «модели» — персонажи с именем, основой и темпераментом — и
автоматическое сохранение всех переписок.

## Что умеет

- Список установленных моделей Ollama (`GET /api/tags`) и проверка соединения.
- Потоковый ответ токен за токеном (`stream: true`) или обычный JSON-ответ.
- Кнопка «Стоп» — генерацию можно прервать на середине.
- Markdown в ответах: **жирный**, *курсив*, `код`, блоки кода, списки, ссылки.
- Настройки сохраняются в `user://ollama_chat.cfg`: адрес сервера, модель,
  системный промпт, температура, стриминг.
- **Переписки сохраняются автоматически** — список диалогов слева, возврат к
  любому из них, переключение и удаление. См. ниже.
- **Свои модели (персонажи)** — настройка уже установленной модели: имя, основа,
  темперамент. См. ниже.

## Свои модели: имя, основа, темперамент

Обучить модель внутри приложения нельзя, зато можно описать её характер.
Кнопка **«+ Создать»** в блоке «МОИ МОДЕЛИ» открывает форму:

| Поле | Что это |
| --- | --- |
| **Имя** | Как модель называется в чате: «Бородач», «Редактор», «Пират». |
| **Основа** | Уже установленная модель Ollama, которая будет отвечать (`llama3.2:latest`, `qwen2.5-coder:7b`, …). |
| **Темперамент** | Кнопки-черты, которые нажимаются и отжимаются: «Дружелюбный», «Сарказм», «Коротко», «Подробно», «Учитель», «Честно о незнании» и др. |

Из имени и темперамента приложение собирает системный промпт — его видно в
форме в блоке **«Системный промпт — предпросмотр»**. Взаимоисключающие черты
(например, «Коротко» и «Подробно») отжимают друг друга автоматически.

Как это работает:

```
«Бородач» + основа qwen2.5-coder:7b + темперамент [Дружелюбный, Коротко]
   ↓
системный промпт
   Тебя зовут Бородач.
   Ты — собеседник в чате на локальной модели «qwen2.5-coder:7b».
   Твой темперамент:
   — Общайся дружелюбно и тепло, обращайся на «ты», подбадривай собеседника.
   — Отвечай максимально коротко — обычно 1–3 предложения…
   ↓
POST /api/chat { model: "qwen2.5-coder:7b", messages: [system, …] }
```

- Персонажи хранятся в `user://personas.json`.
- Выбранный персонаж подсвечивается в шапке чата (`Бородач · qwen2.5-coder:7b`),
  его имя подписывает ответы.
- Если в «БАЗОВЫХ МОДЕЛЯХ» выбрать другую модель, она станет основой текущего
  персонажа (об этом сообщит подсказка внизу).
- «Настроить» — правка имени, основы и темперамента; там же «Удалить» (в два
  нажатия, чтобы случайно не потерять персонажа).
- «— без персонажа —» возвращает обычный режим: отвечает выбранная базовая
  модель, а системный промпт из настроек используется как есть.

## Переписки

Диалог сохраняется сам — ничего нажимать не нужно. В сайдбаре, в блоке
**«ПЕРЕПИСКИ»**, виден список всех диалогов (заголовок + когда обновлялся):

- Заголовок берётся из первого сообщения пользователя, переименовывать вручную
  не нужно.
- Запись на диск происходит после каждого сообщения и после ответа модели, так
  что при аварийном закрытии ничего не теряется. Если приложение закрыли во
  время генерации, уже написанное пользователем сообщение остаётся в файле.
- При запуске открывается последняя переписка вместе со всеми сообщениями.
- Каждая переписка помнит своего персонажа и модель: открыли старый диалог —
  персонаж и модель переключились сами.
- **«+ Диалог»** — новый диалог. Пустые диалоги не создаются: переписка
  появляется в списке только после первого сообщения.
- **«Удалить»** удаляет открытую переписку (в два нажатия, чтобы случайно не
  потерять).
- Если ответ модели сорвался, а сообщение было единственным — пустая переписка
  не остаётся в списке.

Формат — один JSON на диалог в `user://chats/<id>.json`:

```json
{
  "id": "c_123456_1",
  "title": "Привет! Расскажи про космос",
  "created_at": 1762540000,
  "updated_at": 1762540060,
  "persona_id": "p_98765_1",
  "persona_name": "Бородач",
  "model": "qwen2.5-coder:7b",
  "messages": [
    {"role": "user", "content": "Привет! Расскажи про космос"},
    {"role": "assistant", "content": "…", "speaker": "Бородач"}
  ]
}
```

## Запуск

1. Установите [Ollama](https://ollama.com/download) и запустите её:
   ```bash
   ollama serve
   ollama pull llama3.2
   ```
2. Откройте проект в Godot 4.7+ (или запустите собранный бинарник) и нажмите F5.
3. В приложении: `http://localhost:11434` → «Обновить список моделей» → выберите
   модель → пишите.

Горячие клавиши в поле ввода: `Enter` — отправить, `Shift+Enter` — новая строка,
`Ctrl+Enter` — тоже отправить.

## Тесты

```bash
# мок-сервер Ollama (список моделей, стриминг, ошибки, отмена)
python3 tools/mock_ollama.py --port 11499 &

# логика: Markdown, клиент Ollama, хранилище персонажей
godot --headless --path . --script tests/run_tests.gd

# интерфейс: чат, персонажи, сохранение/возврат/удаление переписок
godot --headless --path . --script tests/run_ui_test.gd
```

Скриншоты для документации (нужен X-сервер):

```bash
python3 tools/mock_ollama.py --port 11499 &
xvfb-run -s "-screen 0 1280x900x24" godot --path . --script tools/screenshot.gd
```

## Структура

```
scenes/main.tscn          интерфейс: сайдбар, чат, поле ввода
scripts/main.gd           логика экрана, связь клиента, персонажей и интерфейса
scripts/ollama_client.gd  HTTP-клиент Ollama (стриминг, отмена, ошибки)
scripts/personas.gd       персонажи: каталог темпераментов, JSON, сборка промпта
scripts/persona_editor.gd форма «Новая модель»: имя, основа, темперамент
scripts/chat_store.gd    переписки: JSON-файлы, заголовки, время, удаление
scripts/chat_bubble.gd    пузырь сообщения
scripts/markdown.gd       Markdown → BBCode
scripts/ui_theme.gd       тёмная тема кодом
examples/chat_overlay.gd  пример: чат как меню поверх игры (Esc)
tests/                    headless-тесты логики и интерфейса
tools/mock_ollama.py      заглушка API Ollama для тестов
```
